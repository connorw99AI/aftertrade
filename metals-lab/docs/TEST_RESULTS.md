# Test results

Environment: Linux cloud container, Python 3.13.16, pandas 3.0, numpy 2.5, FastAPI 0.162, Node 22, Next.js 15.5.27.
All tests run against the built-in `SimTerminal`. No real MT5 terminal is used. The gateway refuses `order_send` to a non-simulated backend while tests run.

```
cd metals-lab/backend && python -m pytest tests
195 passed (about 25 minutes in the container; the Assessor and backtest tests dominate)
cd metals-lab/dashboard && npx tsc --noEmit && npm run build
typecheck clean; static export built
```

| File | Covers |
|---|---|
| `test_strategies.py` (46) | Eleven strategies with full metadata and citations. Every strategy emits both OPEN_LONG and OPEN_SHORT with correct stop placement. CLOSE_LONG and COVER_SHORT are distinguished. No lookahead: indicators computed on truncated data equal those on full data, for every column, at random cut points. Sizing uses the bot's own equity and skips trades whose minimum lot exceeds the budget. Pair strategy produces two-leg groups. Unknown parameters are rejected. |
| `test_instruments_sessions.py` (10) | Discovery rejects a stock CFD named GOLD and requires an explicit choice when several contracts qualify. Contract kinds are classified. Lot and price rounding, filling-mode selection, DST-aware server clock, measured offsets, session windows and closures, MQL5 export parsing, London-open DST shift, gap inference. |
| `test_backtest.py` (22) | Next-bar-open fills at ask/bid. Commissions. Stop gaps fill at the worse open. Ambiguous bars assume the stop first, and ticks resolve them. Short stops use the ask. Lot rounding and minimum-lot skips, margin rejection, swap at rollover, seeded rejections and partial fills, determinism, reliability labels, daily-loss pause. |
| `test_ledger_guard.py` (12) | Equal-share (1/22) snapshot taken once. Capital isolation between bots. Idempotent deal booking. Short proceeds are never spendable. Allocation changes need funding, a reason and an operator. Live, contest, unknown and disconnected accounts are rejected. Live account blocked at the order boundary. Non-sim backend refused under test. Fingerprints hide the login. Netting accounts are blocked. |
| `test_pipeline.py` (37) | Auditor has no order capability. Executor refuses: no auditor, no risk, forged signature, approval for another proposal, expired approval, replayed approval. Risk engine rejects proposals without an audit approval. Not armed means nothing is sent. Account switch disarms and revokes approvals. A live account found mid-run disarms. Duplicate prevention. Server-side stop attached; an unprotectable position is closed. Partial fill and partial close produce no popup until the full close, with net including costs. Unrealized changes produce no popup. Manual trade and deposit raise blocking alerts and the deposit is not distributed. Closes still work while paused or killed. Timeout followed by restart recovers ownership from terminal records. Disconnect and reconnect. News outage requires manual review while exits still pass. News blackout delays with a reassessment time; a stale calendar is UNKNOWN. Stale-quote and spread-blowout delays. Risk limits and stop validation. Shadow mode sends nothing. |
| `test_api_research.py` (15) | Dashboard API contracts. Arming from the dashboard only works from this PC, with the typed phrase, on a verified demo account, and never while the kill switch is on; disarm always works. Bot controls and parameter-change rules. API token enforcement. Backtest endpoint labels output as historical replay. Dataset versioning, integrity and quality report. Bars built from ticks. Chronological splits and walk-forward windows. Deflated Sharpe penalises more trials. Bootstrap CI. Holdout usable only once. Event-filter opportunity-cost report. |
| `test_e2e.py` (1) | Full simulated run (arm, all 22 bots, 350 bars) is deterministic across runs. The account balance change equals the sum of all bots' booked P&L. One TRADE_CLOSED event per closed trade. |
| `test_monitor.py` (5) | Summary lists every bot with the account strip. Open positions show live P&L, distances to stop and target, and protection. Manual close goes through the full pipeline. Activity feed and decision funnel. Trade history and CSV export. |
| `test_thoughts.py` (17) | Each bot's one-line thought and readiness count only its own side, name the missing condition, a failing filter or the metal that is off duty. "About to enter" lists bots one condition from an entry. Trades record the rule version they opened under; older databases gain new columns. Daily profit lock, losing-streak pause, entry guard. Minimum lot never risks more than the cap. Settings updates edit `config.yaml` once and keep everything else. Every bot starts on both metals all day (S02 on its Asian hours). The launcher re-splits a running lab to 1/22, keeping every trade. |
| `test_optimise.py` (12) | Assessor tuning: 60/20/20 time split, changes tried in both directions, rounds confirmed on the untouched final period, overfit changes not offered, key failures named. Only a passed tuned change can be applied. Clear suggestions and clear history. Nothing goes to the Engineer until sent. Each closed trade gets a note. Assess and Test all run real backtests. |
| `test_review.py` (8) | Trade review finds a losing session and narrows that metal's window, sets each metal on its own, needs enough trades, flags give-back, gives nothing on a small sample. Live exit classification. Review and test-a-change via the API. Export report has runs and no account identifiers. |
| `test_assessor.py` (4) | Review runs automatically when a trade closes. History shows entry and exit per leg. Review all. Date-range download then backtest. |
| `test_lab.py` (4) | Missing history gives a plain error. Fetch then backtest on terminal history in the account currency. Run all and clear. FX from tick value. |
| `test_ranking.py` (2) | Bot stats; ranking needs trades and profit, then the smallest drawdown. |

Manual checks done here: the dashboard is served by the API in simulated mode and checked in a headless browser after each change (Lab, Assessor, System pages, the disarm confirmation). The simulator has no open trades, so the in-trade card layout is covered by type checks, not seen.
